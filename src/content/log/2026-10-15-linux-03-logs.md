设备在现场死机，拿回来一开机，日志全没了。板端日志要按「实时、落盘、断电保留」三个层次设计。

## 实时

`journalctl -f` 或 `tail -f` 看当前状态。应用的关键状态变化打一行，不要打循环里的每一帧。

## 落盘

```c
/* 按大小滚动，保留最近 N 个文件 */
void log_write(const char *msg)
{
    FILE *fp = fopen("/data/log/app.log", "a");
    if (!fp) return;
    fprintf(fp, "%s %s\n", now_str(), msg);
    fclose(fp);
}
```

每次 `fopen/fclose` 性能一般，但对低频状态日志足够，而且掉电时不会丢缓冲区。高频日志用 `O_APPEND` + 定期 `fsync`。

## 断电保留

- 日志放在独立 data 分区，rootfs 只读也不影响；
- 关键状态另写一份 ring buffer，固定大小，覆盖最旧的；
- 掉电检测用 GPIO 中断或看门狗，触发后 `sync` 再关机。

```bash
# 限制 journal 总量
journalctl --vacuum-size=64M
```

## 该记什么

1. 启动时的版本号、配置摘要；
2. 状态机迁移，带原因；
3. 错误码和重试次数；
4. 关键操作的耗时。

不要记录每帧数据，也不要把密码和完整配置打进日志。
